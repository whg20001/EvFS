# 每日三省 · 设计交接包

「每日三省」是一个网页端的每日学习复盘应用：用户每天把学到的内容**复述**给应用，AI 先**确认**知识点、再**追问**说不清的地方、**补全**遗漏，然后**出题考核**，最后按**艾宾浩斯遗忘曲线**安排复习，并在后台记录完整的学习轨迹用于复盘。

这个文件夹包含实现所需的一切：截图、设计令牌、组件与交互规范、逐页说明、数据模型，以及生成设计稿的 Figma 插件源码。

> **给实现者（Claude）的第一句话：** 这是一个**新项目的前端设计稿**。先读完本文件和 `specs/data-model.md`，再按「实现顺序」逐步进行。截图里的文案和数字是示例数据，要接真实数据，不要写死。

## 设计语言（一句话版）

冷灰底 + 白卡片 + **雾蓝主色 rgb(174, 197, 243) / #AEC5F3**。主色块上的文字一律用深蓝 `primary-800`（对比度 5.8:1），**不要用白字**（只有 1.7:1）。
标题用思源宋体（Noto Serif SC）加粗，正文用思源黑体（Noto Sans SC），数字用 Inter。
朱砂 `accent-600` 只用于「今天」和复习节点；成功 / 警告 / 错误三色只表达学习结果（已掌握、待巩固、有误解）。

## 实现顺序

1. **基础**：引入 `tokens.css`（或把 `tokens.json` 接入 Tailwind 主题），加载字体，建立全局样式和 `:focus-visible`。
2. **基础组件**（`specs/components.md`）：Button、Tag、Card、Segmented、IconButton、ProgressBar、Ring、SearchField、NavItem。先做一个组件演示页，与 `00-style-guide.png` 对照。
3. **应用外壳**：侧边栏 + 顶栏 + 主区域，含响应式（`specs/interactions.md`）。
4. **01 今日复述** → 5. **02 AI 追问与补全** → 6. **03 每日测验**：这是核心闭环，先用假数据跑通流程。
7. **04 复习计划**（排期规则见 `specs/04-review.md`）→ 8. **06 知识点详情** → 9. **05 学习复盘**（图表最后做）。
10. 接入后端与 AI（`specs/data-model.md`），统一处理空状态、加载、错误和无障碍。

## 必须遵守

- 颜色、字号、圆角、阴影**只用令牌**，不写死十六进制值或像素字号。
- 主色块（`primary-500`）上的文字和图标用 `primary-800`；白底上的主色文字用 `primary-700`。
- 状态色不单独表意：每个状态都同时有文字（「已掌握」「逾期 1 天」），进度条旁边都有数值。
- 数字样式 `.text-num-*` 用的是 Inter，**没有中文字形**：单位（天、个、%以外的中文）放在相邻的中文文字里。
- 图标统一用 24 网格、1.8 描边的线性图标（截图中的图标形状接近 Lucide，可直接用 `lucide` 图标库）；纯图标按钮必须有 `aria-label`。
- AI 生成的内容（补全、讲解、周报）都要标明「AI」来源，并允许用户拒绝或修改。
- 删除笔记、移除附件需要二次确认或可撤销。

## 待产品 / 后端确认（实现时请先问，不要自行假设）

- AI 服务选型、调用方式和费用上限；追问轮数（设计稿为每轮 5 题）和测验题量（8 题）是否可配置。
- 「完整度」对比的「标准知识点」从哪里来：AI 现场生成，还是有课程 / 教材知识图谱？
- 「掌握度」的计算公式（设计稿只给了结果，建议见 `specs/data-model.md`）。
- 文件解析与 OCR：PDF、Word、图片公式识别用哪个服务；单文件 20 MB 上限是否合适。
- 语音复述：浏览器端识别还是上传音频到后端转写。
- 账号体系、数据导出（「导出报告」的格式）和隐私政策。

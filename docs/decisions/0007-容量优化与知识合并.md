# ADR 0007：容量优化、知识合并与复习个性化

2026-10-22，第四批实施。范围为按测量结果优化存储、知识合并，以及进一步个性化。

## 容量证据与取舍

`npm run benchmark:storage` 只创建系统临时库，不加载私人环境或数据库，完成后删除临时数据；不调用模型。固定合成样例包含 1,000 个知识点、500 份约 18 KB 文本资料、365 天复述、1,095 份测验、3,285 条证据及 3,285 次已结束任务。它覆盖容量目标，不代表真实用户的内容长度和行为分布。

同一机器（Node 22.23.2、i5-14600KF）的前后结果：

| 测量项 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首次公共状态 JSON | 21,046,816 bytes | 6,140,295 bytes |
| 整行聚合 JSON | 22,253,679 bytes | 6,771,379 bytes |
| 草稿保存中位耗时（5 次） | 365 ms | 199 ms |
| 任务结果写入中位耗时（5 次） | 349 ms | 192 ms |
| 状态投影及 JSON 序列化（5 次中位数） | 47 ms | 27 ms |
| 检索（5 次中位数） | 254 ms | 273 ms |
| 冷启动（1 次） | 478 ms | 460 ms |
| 向空库恢复（1 次） | 1,701 ms | 1,646 ms |
| 完整 JSON 导出（1 次） | 198 ms | 191 ms |
| 进程峰值 RSS | 1,072 MiB | 1,178 MiB |

原始记录：[修改前](../benchmarks/phase-four-before.json)、[修改后](../benchmarks/phase-four-after.json)。写入测量包含仓库事务、校验及 SQL；状态测量不含网络和浏览器渲染。样本数有限，最大耗时也保存在 JSON 中，不视为延迟承诺。检索未优化，内存峰值增加；仍需为 PGlite 和全量内存快照预留空间。

测验和证据占原聚合约七成，因此只拆这两类快速增长的正文。物理 schema 升至 **v4**：`app_learning_records(kind,id,value)` 保存正文，聚合保存 `{id}` 索引。未改变的记录不写；新增分批，修改/删除逐条，和聚合、文档、任务、回执在同一事务内提交。校验、SQL、COMMIT 或迁移失败均保留旧库与缓存。v1/v2/v3 升级及升级前只读导出均受已有独占锁保护；损坏、孤立、缺失或内联记录拒绝加载。

`AppData.schemaVersion` 仍为 1，导出是完整逻辑数据；新增可选合并字段和偏好随备份保存。新程序支持旧备份，旧程序不保证支持新字段或物理 v4。部署前的停服备份与回退步骤见 [README](../../README.md#物理-schema-v4-升级临时库验证通过)。本次验证仅向内存或临时库执行迁移/恢复命令，没有操作真实账号、授权或付费模型。

## 首次同步和详情

- Web 使用 `GET /api/state?compact=1&since=...`；已交卷测验返回带 `detailsOmitted` 的摘要，证据返回明确的 summary 结构，避免把未加载详情伪装为空答案。旧客户端不带 compact 时保留完整公共投影。
- `GET /api/quizzes/:id` 复用公共题目投影；未交卷时仍不泄露后续题、参考答案或 rubric。完成页按需读取，刷新评价时保留已挂载的核对输入，待新详情加载后恢复保存。
- `GET /api/knowledge-points/:id/evidence` 每页默认 20、最多 50 条，包含总数及下一页 offset，后续页使用 revision 校验；冲突要求重读第一页。目标知识聚合其合并来源的证据，原知识页仅展示原记录的证据。
- 完整与摘要同步分别缓存基线，指纹仍只针对公共投影；详情接口继续鉴权。历史统计保留原知识 ID，页面可追踪原题。知识列表、学习日和统计记录逐批显示，避免首次创建大量 DOM。

其余实体仍在初始状态中，文档正文、任务和历史正文仍常驻服务端缓存。没有把此次优化描述为全面分页、全面规范化或内存上限控制。

## 知识合并

从知识详情选择目标，先 `POST /api/knowledge-points/:id/merge-preview` 查看来源、标签、证据/会话数量及现有卡片；再明确选择一张现有卡片，确认 `POST /api/knowledge-points/:id/merge`。没有现有卡片时明确使用 null，不创建新卡。提交同时验证预览 revision，幂等回执防止重复执行。

目标保留名称、描述、理解，来源及标签去重并集；来源变化保存新内容版本。标签超过上限时拒绝，要求先整理，不能静默截断。原知识点保存合并关系并归档，转为只读，原内容、个人理解和内容历史均可追溯。禁止合并到自身或已合并记录；后续可把目标再合并到另一个当前知识，恢复校验拒绝循环和丢失目标。

保留卡的原始 `knowledgeId` 不变，`currentKnowledgeId` 指向之后学习的知识；到期时间、暂停状态和全部 FSRS 参数原样保留。其余卡使用 `retiredAt` 永久停用，无法恢复或再次开始。历史题目、作答、评价版本、复习事件和任务输入均不改写，参数不平均，历史排期不重放。历史卡的原始身份可与当前学习目标分别追踪。

有活动任务、涉及两点的未结束学习、或关联卡片的未结束复习时拒绝合并。UI 检测本页未保存的编辑并要求先保存或重置。归档与合并不同，已合并原记录不能通过“恢复归档”重新进入队列；本次没有实现页面撤销合并或永久删除。

## 复习个性化

偏好新增 `reviewOrder: due | weakness` 与 `reviewBatchSize: 1..100 | null`；默认仍为到期优先、不限每轮数量。旧客户端省略字段时保留已保存值。保存沿用确认、revision CAS 和活动任务保护。

`GET /api/reviews/plan` 只读生成本轮队列：只选已到期、未暂停、未归档、未停用的现有卡，不改排期。近期失分优先使用最近 30×24 小时的证据，最多最近 5 次同类独立作答；延迟证据达到 3 次时优先使用，否则考虑即时证据，均不足 3 次则按到期时间。仅纳入已交卷、同模式、已评分、非辅助、非跳过、非人工自评、无未解决争议的记录，并按原题去重。累计得分/满分之比用于排序，平手按到期时间和 ID；合并后的证据归入当前知识，但历史 ID 不变。

UI 展示排序依据、样本数量和演示标记，明确这不是掌握率。每轮数量只限制本轮队列，可主动开始下一轮；不限制一天总量，也不禁止手动单卡复习。队列仍需逐次主动开始，不预先请求模型。未进行自动 FSRS 参数训练、保持率估计或真实学习效果验证；评级仍为第三批的 mapping-v1。

# ADR 0003：全文优先、稳定前缀与自动旧知识联想

状态：已采纳。部分取代 [ADR 0002](./0002-本地检索与显式知识关联.md) 中的“固定检索配额”“最近两轮问答”“范围确认时手动关联旧知识”“Anthropic 无独立资料断点”。

## 背景

ADR 0002 的检索按固定字符配额选段：资料即使完全放得下也只发片段；追问只带最近两轮；随着问答推进，每次请求的资料片段都可能不同，厂商前缀缓存几乎无法命中。旧知识关联要求用户在确认范围时手动搜索、勾选，实际很少使用，而真正想要的是“出题时把相关旧知识结合进来”。

## 决定

### 1. 全文优先，超预算才检索

- 授权来源的总成本（按 JSON 转义后的字符与 UTF-8 字节计）在剩余输入预算内时，原文全部发送，预览显示“全文发送”。
- 超出时按**实际剩余空间**做 BM25 检索：每个命中来源先得到最佳块，再按全局分数补充命中块、扩展相邻块；无命中来源取有限首尾背景；空间不足时明确标出“此来源正文未发送”。片段保持原文顺序并带 `[原文行 a-b]`。
- 预算由宿主在 H2 之前离线规划（`apps/api/src/input-plan.ts`）：先用“来源正文置空”的骨架测出系统提示、Schema、知识点等固定开销，剩余空间才分给来源。grade 与连接诊断不做检索。

### 2. 稳定前缀

- 追问（followup）与学习会话测验（无 recall 的 quiz）属于同一“范围”。规划时使用同一个规范骨架和一个与轮次无关的动态预留（`min(8000 字符, 剩余/4)`，字节同理），因此同一范围内每次请求选出的来源完全相同。
- 用户消息拆为两个文本块：稳定块 `{sources, points, related?}` 在前，动态块 `{kind, turns | count | recall}` 在后。followup 与 quiz 共用同一份系统提示（含两套输出 Schema，按 `kind` 执行），提示版本升级为 `learning-v5`。
- 问答超出预留时，先把较早轮次的作答/反馈替换为省略标记（最新一轮保持完整），不重切来源。只有最新一轮本身就超过预留（小窗口模型、超长作答）时，才针对**这一次请求**按“来源置空、带实际轮次”精确测出的剩余空间一次重新检索来源（来源成本可逐项相加，结果必然放得下）：放弃一次缓存命中，换取不截断最新作答、也不让 H2 平均切割所有来源。
- 复习测验（含 recall）不属于学习会话范围，没有动态预留，按自己的完整预算规划。

### 3. 厂商缓存

- Anthropic：开启短缓存时，仅对 followup 与会话 quiz 在稳定块上放置唯一一个 ephemeral 断点；Pi 默认添加的系统提示/末尾断点被移除。extract、复习 quiz、grade 不放断点（不会被复用，写缓存反而更贵）。
- OpenAI API key：依赖厂商自动前缀缓存，加上按学习会话 HMAC 生成的 `prompt_cache_key` 亲和键。
- OpenAI OAuth/Codex：无需专门改动。稳定前缀（第 2 节）对它同样生效，请求带亲和键（`prompt_cache_key`），由上游自动前缀缓存；Responses 接口没有显式断点可加，也不额外发送未在 Codex 端点验证过的缓存字段。上游若返回缓存读取 token，会与其他厂商一样照实记录；订阅额度下节省无法换算成金额，不做承诺。
- xAI（Grok）：API key 与 SuperGrok/X Premium 订阅授权（设备码，与 Grok Build 同一授权）都走 Pi 的 Responses 接口。按 xAI 官方建议，同一会话使用稳定的 `prompt_cache_key`（即上面的亲和键，Responses 接口对应 Chat Completions 的 `x-grok-conv-id`），且只追加、不改写前缀——这正是第 2 节的稳定块。没有显式断点；命中部分按约 0.25 倍计费（订阅授权下同样无法换算成金额）；不额外发送未验证字段。
- 稳定前缀只提高命中概率，不保证命中、TTL 或节省金额；`none` 仍不保证厂商完全不缓存。

### 4. 旧知识联想（自动、受设置控制）

- `learningPreferences.associationEnabled`，默认关闭，设置页“旧知识联想”开关，保存规则与排期/缓存相同（确认、CAS、活动任务期间禁止）。
- 开启时，宿主在两个时点用本地 BM25 自动选出最多 3 个旧知识点（至少 3 个多字词项命中）：学习范围确认时（冻结到会话，供追问与会话测验使用）、复习提交回忆时。不再事先展示给用户，也取消了手动搜索/勾选面板；确认接口不再接受 `relatedKnowledgeIds`（未知字段被忽略）。
- 旧知识以 `related`（id、标题、描述、内容版本）进入模型输入，**不是来源**：不能被引用，不扩大考核范围，不改写旧知识点。题目可以通过 `relatedKnowledgeIds` 标记结合了哪些旧知识，但题目的 `knowledgeId`、`sourceIds` 和证据只属于当前知识点；组合题只影响当前知识点的证据与排期。
- 与“复用知识点”仍是两回事：复用会更新旧知识点的当前内容；联想只在出题和追问时结合。

## 后果与边界

- 小资料不再被无谓裁剪；大资料按真实剩余空间取更多相关内容。
- 共用系统提示约 3,320 字符 / 5,262 UTF-8 字节。8K 上下文窗口的模型在预留 4096 输出 tokens 后放不下追问/测验的固定开销，会在入队前被拒绝；需选用更大窗口的模型或降低输出预留。
- 动态预留会让会话范围内的来源比“只看当前轮次”时略少，这是稳定前缀的代价。
- BM25 联想是词面相关，不是语义判断；旧知识描述可能有误，提示词要求模型“不为结合而牵强关联”。
- 逻辑备份与物理 schema 不变；新字段均可缺省，旧数据按“关闭联想”处理。历史 run 的 `learning-v4` 版本不回写。

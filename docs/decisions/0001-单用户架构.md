# ADR 0001：单用户架构与有限聚合

- 状态：架构决定已接受；本轮实现通过离线回归，见[最终验证记录](../审查修复记录.md#最终验证)。
- 范围：自用应用，不包含公开多人服务或真实模型质量验收。
- 关联：[稳定规格](../产品与架构规格.md)、[当前状态](../实现状态与偏差表.md)。

## 背景

旧手册同时描述多 worker 租约、工具提案、规范化实体表及 SSE，与已运行的单用户无工具实现不一致。需要减少场景不需要的运维与协调机制，又不能取消真实存在的并发、浏览器攻击和计费风险。

## 决定与理由

### 1. PGlite + Drizzle，保留适量聚合

选嵌入式 PostgreSQL 以免自用部署额外维护数据库服务，同时保留 SQL、事务和可审查迁移；Drizzle 负责显式 schema/查询。初期学习流程集中在同一事务内，聚合让流程一致性容易推理，不为每个逻辑实体预先设计仓储接口和表。

原“所有数据一行”把资料原文和高频业务写混在一起。物理 schema v2 将原文拆到 `app_documents`；H2 保留全文后，v3 再把 AI 任务输入拆到 `app_run_tasks`，避免每次写入重写全部历史输入。其余仍聚合，并使用进程内快照缓存、串行事务/CAS。这样先处理最大的重复读写源，不冒充全面规范化或消除了全聚合内存/写校验成本。逻辑 AppData 备份仍为 schemaVersion 1。

替代方案：独立 PostgreSQL 服务会增加当前不需要的部署负担；立刻全实体拆表迁移成本大；继续把原文留聚合会维持已识别开销。若实测逻辑数据与延迟越过工程目标，再按热路径拆实体，不以 PGlite 目录固定占用作性能结论。

代价：单目录单进程，不支持横向扩容。升级前停服并运行新版 `npm run data:export -- ./backup-before-v3.json --before-migration`，加锁后在 SQL 只读事务中完整导出已有物理 v1/v2/v3，不初始化或升级 schema；不需旧程序副本，PGlite 自身 WAL 恢复可能写盘；新物理库不可由旧程序直接打开，不能承诺无备份降级。

### 2. 无工具、单请求结构化任务

提取、追问、出题与评分具有已知输入/输出，宿主可直接构造最小上下文并校验结果。单次 Pi Agent 请求保留 Provider 适配、取消和用量观测，不需要模型自主取资料或修改数据库。

不实现 `get_*` / `propose_*` 工具、候选提案存储、工具并发调度或无限修复循环。相比工具式 Agent，减少权限面、不可预测调用次数、私有答案泄漏路径及失败清理。代价是资料选择须由宿主确定，不能把确定性节选宣传成语义检索能力。只有明确任务需要工具且有隔离/计费方案时再立 ADR。

### 3. 单执行器，不做多 worker 租约

同一 PGlite 目录已经单进程独占，集群租约没有实际消费者。本轮采用持久化入队后唤醒执行器，不再空闲周期性读取全聚合。仍保留 run/attempt 和 CAS fencing，因为取消、异步迟到、多个标签页及重试是单用户也会遇到的竞争，不等于有多 worker 接管。

崩溃后的未知收费任务不自动重放。仅已知 CAS 草稿/理解/回忆暂存回执在后续新命令内按 24h / 最多 2,000 条清理；含 runId、未知操作及其他非暂存收据长期保留，不是所有非计费 command 都自动删除。恢复旧备份不能保证永久去重。扩多进程前须重新选择共享数据库和任务领取协议。

### 4. 不把未消费的 SSE 当主要通道

客户端既无 EventSource 消费，也不公开结构化出题的原始 token 流。维护第二套状态 SSE 会增加无效读取与鉴权生命周期。本轮删除旧 SSE，采用 `/api/state?since=revision` 的 unchanged/snapshot/delta 协议和按需全文；16 个基线只存指纹，未知版本回快照，初载仍为全部公共实体（资料仅 metadata）而非分页。允许有目的的客户端查询，不承诺所有场景零轮询。代价是客户端仍需正确处理增量、回退和刷新时机；本轮相应 API/E2E 回归已通过。

### 5. 保留身份、归属、CSRF 与 Origin

这不是无意义“多重鉴权”：

- 密码和签名会话回答“是谁”；HttpOnly 降低脚本读 Cookie 风险。
- 归属校验防止接口接受任意资源 ID，单用户也不能绕过访问边界。
- Cookie 会自动随浏览器请求发送，CSRF 防止其他页面借已登录浏览器执行写操作。
- Origin 校验限制允许的来源，与 CSRF、SameSite 分别提供防线，不由 Host 自动放行。

去掉这些检查并不能简化成安全自用工具，尤其 Web 为 WSL 监听 `0.0.0.0:3010`。API 保持回环和 `trustProxy:false`。Next 自定义 Node 入口从 socket `remoteAddress` 取 IP、剥离客户端转发头，以 HMAC 绑定 IP/时间/方法/path；API 仅对 loopback 来源且有效签名采纳此 IP。选择受控入口是为了保留 WSL 可达性又不相信任意 XFF；代价是需维护签名和代理边界的回归。实现已通过离线代理/API 与真实 Next E2E 回归，不据此宣称已完成公网安全审计或 Windows→WSL 跨宿主机人工验收。Web dev/start 必须走 npm scripts → `apps/web/server.mjs`；`API_INTERNAL_URL` 仅 literal loopback origin（127.* / ::1），不接受 localhost hostname 或远程 API。仅 dev `/_next/hmr`（可 query）放行 Upgrade，生产及未知路由拒绝，退出销毁升级 socket；12 个 Node socket 测试覆盖。NAT 在入口前合并源 IP 时仍无法区分客户端；生产 HTTPS 需独立受控部署，不扩大代理信任。

### 6. 明确不设金额预算，但保留费用风险

当前本人已决定不设置应用金额预算，不能继续把“确认金额上限”当开工阻塞项。仍记录 token、已知/未知费用及适用预留，保留超时、调用次数和显式重试。OAuth 订阅不是免费或无限承诺，OpenAI/Codex OAuth 无上游输出硬限制的确认门槛继续保留。已有可选估算预算可后续显式启用，不能替代厂商硬限额。

## 结果与重审触发条件

工程观察目标为单用户 ≤1,000 知识点 / ≤500 资料 / ≤1 年日常记录，非强制上限或压测保证。超出、读写延迟不可接受、多进程/多人需求或任务确需工具时重审；学习历史不因超目标自动过期。

真实模型质量与 FSRS 长期效果需要独立评估，离线测试不提供这类保证。现阶段不为了“未来可能需要”增加通用事件总线、微服务或多 Agent 框架。

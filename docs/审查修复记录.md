## 升级与边界

本轮涉及物理 schema 升级。启动新版前，先停止对应 API，并备份当前模式：

```sh
npm run data:export -- ./backup-before-v3.json --before-migration
```

此路径兼容已有物理 v1/v2/v3，加独占锁后在 SQL 只读事务中完整导出，不初始化或升级 schema，不需要找回旧程序。临时 v1 CLI 测试已验证导出后 schema 仍为 1、文件权限 0600、wx 拒绝覆盖。PGlite 自身可能执行 WAL 恢复，锁文件也有生命周期写入，不承诺磁盘零写。JSON 私密、未加密。保存成功后再由用户启动/迁移新版。mock/live 分别备份；学习备份不含 OAuth vault，`SESSION_SECRET` 不应更换。

已启动升级后的物理 v3 库不能直接交给旧程序打开。没有代替用户执行真实备份、迁移、清空、解锁、服务启动或真实模型请求。

保留的工程边界：初次状态仍载入全部公共实体（资料仅 metadata，不是分页）；文档以外仍为聚合，仍有全聚合内存/写校验成本；未做大库性能压测；真实 FSRS 排期默认 false，不开卡、不排期、不推进既有卡，启用不追溯补卡；NAT 若在受控 Node 入口之前合并客户端 IP，不能靠不可信请求头恢复。含 runId、未知操作及其他非暂存收据长期保留，但恢复旧备份或清空不能保证永久去重。

Web dev/start 必须经 npm scripts → `apps/web/server.mjs`，不支持绕过入口直接 `next dev/start`。`API_INTERNAL_URL` 只接受 literal loopback origin（127.* / ::1），非 localhost hostname/远程 API。Windows→WSL 真实网络访问本轮未人工验收；生产 HTTPS 需独立受控部署，不扩大代理信任。真实模型质量、真实授权/刷新/账号权限、长期学习效果及公网安全审计均未验收。

本轮未操作真实库、真实锁或用户服务；3010/4000 在集成检查时无监听，仅是当时状态，不替代用户下次维护前的进程检查。

## H2 补充修复

复核曾发现 16,765 字符的任务在 48K 内仍被固定 6K/3K 规则截断；首轮仅复述预览也未包含资料，字符检查未绑定所选模型窗口。本次不通过扩大存档上限或无条件丢弃尾部掩盖问题：

- `contracts/src/context.ts` 去重/范围过滤后先核总预算，够则完整保留；超限才分布或词面选段，标记缺口，保护 Unicode 边界及原始输入。支持字符与 UTF-8 双限额，反复准备已满足预算的任务不会继续裁剪。
- `learning-agent/src/request.ts` 统一完整提示构造与预算：每任务只附本分支输出 Schema；system + schema + user 的 UTF-8 字节作保守 token 估算，预留输出与 512-token 消息/适配余量。宿主点/题目版本元数据不外发。`prepareLearningRequest` 返回要持久化的任务；引擎最终只检查、不偷偷改内容，超限在读取凭据及请求 Provider 前拒绝。新学习提示版本 `learning-v3`，历史版本不回写。
- API 将当前模型策略注入领域事务，所有任务准备共用；正式 grade 提交前预检完整答案及私有 rubric，超限原子拒绝，不锁定答案。新增复述/简答只读 POST 预检，Cookie/Origin/CSRF 保护，只回数字、模型目录元数据及节选条目，不写库、不创建 run/回执、不调用 Provider 或刷新凭据。
- 页面显示包含已上传资料的实际任务预算；live 显示完整提示估算及预留，失败/过期不用旧余额。防抖、abort、输入/版本校验保护迟到响应；保存后再预检才正式提交，草稿/上传/明确跳过仍可用。历史会话资料管理不冒充新任务预览。
- 回归暴露另一个既有时序风险：认证完成但 `/login` 返回导航尚未提交时，编辑区已经可交互，输入可能落在即将替换的节点上。现在子树保持挂载但 hidden/inert，待导航完成再编辑；已有 Cookie 直接访问 `/login` 也能返回。用受控延迟真实 RSC 响应的两个测试验证，不靠 sleep 掩盖。

保留边界：UTF-8 是偏保守的本地规划估算，不是厂商精确分词或接受保证；可能更早节选。窗口来自本地目录，厂商变化、真实账号权限及质量仍需另行验收。输出预留不能给 OpenAI/Codex OAuth 增加不存在的上游硬上限。节选不是摘要/RAG，不能保证所有知识覆盖；预检通过也不等于账号连通。48K 仍是任务 JSON 上限，固定标准/正式答案放不下时必须精简、选择适当模型或跳过，而不是静默截断。

## 问题 1：任务输入随聚合重写（H2 后续）

H2 保留全文后，每条 `run.task` 最多约 4.8 万字，原先都存在单行聚合 JSONB 中；每次写入都要深拷贝、序列化并重写全部历史输入。处理：

- 物理 schema 升至 **v3**：新增 `app_run_tasks(id, task jsonb)`，聚合里的任务只存元数据。新增任务插入、删除任务删除，内容变化才 UPDATE；状态等变化不写任务表。
- v1→v3、v2→v3 在单个事务中完成并以 CAS 推进账本，失败全部回滚。v3 缺失、孤立或残留内联任务都拒绝打开或导出。`--before-migration` 导出兼容 v1/v2/v3。
- 快照的读写拷贝改为共享不可变字符串的 JSON 拷贝（保留 `last_review: undefined` 键），不再用 `structuredClone` 复制全部正文。

| 场景（每条任务 4 万字，同一基准脚本） | 修复前 | 修复后 |
|---|---|---|
| 100 条任务空写入（内存库） | ≈91ms | 4ms |
| 1000 条任务空写入（内存库） | ≈989ms | 20ms |
| 1000 条任务空写入（磁盘临时库，5 次中位数） | — | 16ms |
| 1000 条任务重新打开（磁盘，读全部并完整校验） | — | ≈620ms |

仍有的边界：完整任务仍常驻内存快照，写入时元数据序列化和全量校验仍随条数线性增长（量级已降两个数量级）。验证：`npm run check` 通过；单元 326、集成 91 + 12、E2E 29 全部通过。升级前须停服并按上文用 `backup-before-v3.json` 分别备份 mock/live；未操作用户真实库。

- 已准备任务重试复用冻结输入；新增 `inputPrepared` 区分准备失败、尚无可发送快照的任务，后者可在明确重试时重新准备。执行时仍只拒绝超预算，不偷偷修改输入。
- `learningPreferences` 按模式持久化排期及 none/short 缓存偏好：确认、revision CAS、幂等及活动任务保护。旧数据保留环境排期默认和缓存 none，不修改用户 `.env`。开启不自动补卡，旧知识可单点明确加入；关闭后已交卷复习仍可完成，但不推进排期。
- 引擎仍独立 Agent、一次请求、无自动重试；稳定来源前置，使用目的限定 HMAC 亲和键，连接测试不请求缓存。保留实际缓存读/写 tokens（已包含在总输入），旧记录缺计数标未知，拒绝缓存子计数超过总输入。
- 提示版本 `learning-v4`，历史不回写；逻辑备份仍 v1，物理库仍既有 v3，本次无新增物理迁移。设置/关联/准备状态兼容旧字段缺失，新关联快照恢复时须匹配真实内容历史。`/api/me` 通过内存小型设置投影获得实时能力，不读取 SQL 或复制全聚合。

边界见 [ADR 0002](./decisions/0002-本地检索与显式知识关联.md)：没有付费 embedding、语义近义保证或自动摘要。short 不保证命中/TTL/费用，none 不代表所有厂商完全关闭缓存；Anthropic 当前单 JSON 用户块没有独立资料缓存断点。未验证真实命中率、费用、模型质量或长期学习效果，也未替用户启用排期或短缓存。

## 全文优先、稳定前缀与自动旧知识联想（ADR 0003）

- **检索（修复 1）**：授权来源放得下就全文发送（预览显示“全文发送”）；超预算才按实际剩余空间做 BM25 检索：命中来源先得最佳块，再按全局分数补块、扩展相邻块，无命中来源取有限首尾，空间不足明确标“正文未发送”。删除固定配额 `retrievalTotalChars/retrievalSourceChars/retrievalHistoryTurns`。规划在 API 层离线完成（`apps/api/src/input-plan.ts`），预览与入队共用。
- **稳定前缀（修复 2）**：追问与会话测验用同一规范骨架和与轮次无关的动态预留，同一范围内来源完全一致；用户消息拆为稳定块 `{sources, points, related?}` 与动态块；followup/quiz 共用一份系统提示；提示版本升至 `learning-v5`。问答过长先省略较早作答（最新一轮完整）；仅当最新一轮本身超出预留时，才为这一次请求按精确测得的剩余空间一次重新检索，不让 H2 平均切割来源或截断最新作答。
- **厂商缓存（修复 3）**：Anthropic 开启短缓存时只在 followup/会话 quiz 的稳定块放一个 ephemeral 断点，移除 Pi 默认的系统/末尾断点；extract、复习 quiz、grade 不放。OpenAI 依赖自动前缀缓存 + HMAC 亲和键；Codex OAuth 无需专门改动（同样受益于稳定前缀，带亲和键、依赖自动前缀缓存，没有显式断点可加；上游若报告缓存读取 token 会照实记录，订阅额度下节省无法换算成金额）。设置页按厂商说明缓存行为。
- **旧知识联想**：手动搜索/勾选面板与 `relatedKnowledgeIds` 确认字段移除，改为设置“旧知识联想”（默认关闭）。开启后确认范围与复习提交回忆时自动选最多 3 个旧知识点（BM25，至少 3 个多字词项命中），以 `related` 进入输入，不事先展示、不作来源、不扩大考核范围；题目可用 `relatedKnowledgeIds` 标注结合了哪些旧知识，宿主校验其属于本次 `related`；证据与排期只记到当前知识点。知识详情的历史关联卡片保留。
- **已知限制**：共用系统提示约 5,262 UTF-8 字节，8K 窗口模型在 4096 输出预留下放不下追问/测验，会在入队前拒绝。

## 弹窗确认与 xAI（Grok）接入

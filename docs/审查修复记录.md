## 全文优先、稳定前缀与自动旧知识联想（ADR 0003）

- **检索（修复 1）**：授权来源放得下就全文发送（预览显示“全文发送”）；超预算才按实际剩余空间做 BM25 检索：命中来源先得最佳块，再按全局分数补块、扩展相邻块，无命中来源取有限首尾，空间不足明确标“正文未发送”。删除固定配额 `retrievalTotalChars/retrievalSourceChars/retrievalHistoryTurns`。规划在 API 层离线完成（`apps/api/src/input-plan.ts`），预览与入队共用。
- **稳定前缀（修复 2）**：追问与会话测验用同一规范骨架和与轮次无关的动态预留，同一范围内来源完全一致；用户消息拆为稳定块 `{sources, points, related?}` 与动态块；followup/quiz 共用一份系统提示；提示版本升至 `learning-v5`。问答过长先省略较早作答（最新一轮完整）；仅当最新一轮本身超出预留时，才为这一次请求按精确测得的剩余空间一次重新检索，不让 H2 平均切割来源或截断最新作答。
- **厂商缓存（修复 3）**：Anthropic 开启短缓存时只在 followup/会话 quiz 的稳定块放一个 ephemeral 断点，移除 Pi 默认的系统/末尾断点；extract、复习 quiz、grade 不放。OpenAI 依赖自动前缀缓存 + HMAC 亲和键；Codex OAuth 无需专门改动（同样受益于稳定前缀，带亲和键、依赖自动前缀缓存，没有显式断点可加；上游若报告缓存读取 token 会照实记录，订阅额度下节省无法换算成金额）。设置页按厂商说明缓存行为。
- **旧知识联想**：手动搜索/勾选面板与 `relatedKnowledgeIds` 确认字段移除，改为设置“旧知识联想”（默认关闭）。开启后确认范围与复习提交回忆时自动选最多 3 个旧知识点（BM25，至少 3 个多字词项命中），以 `related` 进入输入，不事先展示、不作来源、不扩大考核范围；题目可用 `relatedKnowledgeIds` 标注结合了哪些旧知识，宿主校验其属于本次 `related`；证据与排期只记到当前知识点。知识详情的历史关联卡片保留。

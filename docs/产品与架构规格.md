# 产品与架构规格

> 稳定规格与已确定决策；对应实现已通过本轮离线回归，命令及结果见[审查修复记录](./审查修复记录.md#最终验证)。离线正确性不等于真实模型或公网验收，逐项状态与未完成项见[实现状态与偏差表](./实现状态与偏差表.md)。启动、OAuth/vault 和费用风险集中见 [README](../README.md)，选型理由见 [ADR 0001](./decisions/0001-单用户架构.md)。

## 1. 产品范围与评价语义

每日三省是单用户自用的主动回忆工具，不是公开注册、团队或计费产品。核心流程：

```text
三段复述 → 确认范围 → 有限追问 → 独立测验 → 留下证据
                                        ↓
                         排期启用且有有效证据 → 单卡复习
```

- 三段输入分别记录学了什么、哪里不清楚、如何应用。草稿可改，提交生成不可变快照；修订不重写旧题依据。
- 资料接收 UTF-8 TXT / Markdown（`.txt`、`.md`、`.markdown`）、粘贴文本和本地解析的文本型 PDF；PDF 保存原文件、页码与全文行号映射，细节见 [ADR 0006](./decisions/0006-文本PDF与复习统计.md)。文本输入拒绝明显二进制、NUL 与不可解码内容。Markdown 是非可信文本，不执行其中代码或自动抓取外链。
- 来源阅读：文档的 `.md/.markdown` 及无扩展名条目默认 Markdown 排版，`.txt` 默认原文；可切换带行号原文用于核对 AI 证据。新粘贴资料未填支持的扩展名时补 `.md`。旧知识和原始复述快照仅按行显示。所有来源支持最大化蒙版，视图同步、焦点循环、Esc/空白关闭和滚动锁定，适配窄屏与深色。
- 排版支持 GFM、只读任务列表、带语言标签的代码块及本地 KaTeX 公式；HTML 转义显示，图片一律文字占位。仅显式 http/https/mailto 链接可由用户主动打开（新窗口、无 referrer），相对/危险协议只显示文字；公式禁用信任命令并限制尺寸/展开次数。渲染器按需懒加载，不修改原始文本与行号。依赖、安全与性能边界见 [ADR 0005](./decisions/0005-笔记Markdown渲染.md)。
- 用户确认知识候选、复用稳定身份或拒绝候选；AI 推断、用户自评和有效作答证据必须区分。
- 原始复述本身可以成为真实来源记录。提取候选至少引用一个本次授权范围内确实存在的 source；“有来源”不代表经过外部事实验证，也不代表原文必然正确。
- 未提及不等于不会，接受补全不等于掌握。无可靠评分或样本时保留待核对 / `null`，不制造综合掌握度、保持率或课程完整度。
- 题目、参考答案、rubric 与所用内容版本固定保存。作答前只公开当前题和允许回看的已答题，不下发私有答案或未来题目。
- 答案草稿不评分，正式答案先保存且不可覆盖，再执行评分；失败不丢答案。跳过不伪装成错误，辅助作答不伪装成独立证据。

## 2. 流程、版本与复习

### 学习与任务分离

学习流程包含范围确认、追问、测验及完成，也支持无测验结束。后台 run 使用 `pending / running / succeeded / failed / cancelled`；run 成功不等于整个学习流程完成。

结束原因按明确请求记录；已完成正式交卷的 `assessed` 不得被后续结束操作覆盖。取消只影响执行任务，离页只暂停交互，均不隐式交卷。

同一会话只允许一个活动模型任务。命令使用幂等键和预期版本；旧 run/attempt、取消后或版本过期的结果不能提交业务状态。进程重启不自动重放可能已收费的请求，须明确重试；连接测试不能通过通用学习重试入口重放。

新任务在输入准备完成后保存 `promptVersion` 与 `promptHash`：后者覆盖应用系统提示、输出 Schema 和实际用户输入块。执行器领取前核对当前内容，不匹配或旧排队任务缺少指纹时返回 `PROMPT_CHANGED`，释放活动状态和未使用的费用预留，不增加调用次数；显式重试创建新记录并绑定当前提示词，保留冻结输入与旧记录。引擎在请求前再次核对。历史已结束任务保持原版本，缺失指纹不补造；此指纹不含 Provider 适配、模型配置与凭据。

运行错误持久化白名单 `errorCode` 与固定中文操作提示，分别记录限流、授权失败、超时、输出限制、格式/引用校验、主动取消与服务中断。未知错误归为 `MODEL_FAILED`，不存 Provider 原文或堆栈。已观测用量和费用预留遵守原有规则，错误分类不触发自动重试；状态 API 只公开安全分类及提示，不公开任务正文或指纹。

### 版本的不同含义

- **草稿 / 聚合 CAS 版本**：用于检测并发覆盖，不是学习内容版本。
- **范围版本**：固定本轮明确纳入的知识和资料；新范围不重写旧问答，后续任务按当前范围过滤资料及追问历史。
- **知识内容版本与快照**：知识稳定 ID 可跨天复用；内容修改保留历史，个人理解及并发保存版本不能冒充内容版本。
- **题目与证据引用版本**：证据绑定题目实际使用的知识内容版本，而不是评分时碰巧最新的版本。旧历史缺少版本时标记未知，不用当前内容补造历史。

交卷后可标记评价争议，或用原评分标准人工核对/明确请求模型复评。分项保存 rubric ID、描述、满分、得分与依据；评价修订递增版本并保留旧评价，正式答案和原题不变。人工核对标记为自评，未解决争议及自评不用于推进后续复习排期；已发生的历史排期不回滚。复评取消、超时、失败、预算拒绝均保留原评价，必须从核对区明确发起新请求，不能通用重试。

知识点名称/描述修改形成新内容版本；标签和归档只递增并发版本。归档退出默认知识列表、检索、联想及复习队列，保留历史引用、来源和卡片；已开始的复习允许保存结果但不推进归档卡片排期。恢复后沿用原到期时间。

### 单卡复习

先保存非空的正式回忆，再把该回忆作为出题输入；同时从该知识点实际引用的原文/已提交复述检索片段，并冻结知识内容版本。缺失来源不从无关全库补造；回忆文本不直接算成正确证据。多题按目标聚合为一次复习结果，卡片 CAS 阻止重复排期；刷新可恢复，放弃不推进间隔。

现有调度采用 `ts-fsrs@5.4.2` 默认权重、目标保留率 0.9，关闭 fuzz 和短期学习。`mapping-v1` 只纳入已评价、未辅助且未跳过的作答：参与作答有未满分则 Again，全满分才允许用户选择评级；同目标后题若已暴露解析则排除其独立性。以实际作答时间而非评分结束时间计算。新卡的初次提醒是 24 小时后，不是掌握证明。

**live 默认 `REVIEW_SCHEDULING_ENABLED=false`，不开新卡、不排期，也不推进既有排期。** 复习页提供需明确确认的应用内设置，保存后覆盖环境默认，不修改 `.env`。启用前须接受实现、参数、评级映射和时区；启用不自动补历史卡，知识详情可单点明确加卡。关闭时仍能完成已交卷复习并保留证据，但不推进排期。mock 的模拟证据和排期与 live 隔离。真实模型评价质量及长期学习效果尚未验证。

## 3. 统一限制与外发范围

唯一常量来源：[`packages/contracts/src/limits.ts`](../packages/contracts/src/limits.ts) 的 `LIMITS`。配置接受范围由 [`apps/api/src/config.ts`](../apps/api/src/config.ts) 校验，浏览器提示应使用相同契约/服务端能力。本轮跨层统一接入已通过离线回归。

| 项目 | 已确定限制 | 语义 |
|---|---|---|
| 三段复述 | 每字段 20,000 字符 | 各字段存档上限，不保证三段全文一次外发 |
| 主题 | 80 字符 | 输入校验 |
| 答案、个人理解、回忆 | 各 12,000 字符 | 正式答案不得为适配模型预算而截短 |
| 模型任务 JSON | 48,000 字符 | 实际模型任务投影序列化长度，含结构/转义，不含不外发的宿主版本元数据；不是 token 或字节 |
| 单个上传文件 | 默认 131,072 bytes，可配置最大 1,048,576 bytes | UTF-8 存档资源上限 |
| 资料数量 | 默认 5，可配置最大 10 | 一次复述资料集合，不是整个资料库上限 |
| 追问 | 默认 3，最大 5 | 有限追问，不是无限对话 |
| 测验题量 | 默认 3，最大 5 | 不使用设计截图中的固定示例题数 |

字符指 JavaScript 字符串长度口径；中文、emoji、JSON 转义与 UTF-8 字节、模型 token 的数量不可直接互换。

### 存档预算不等于模型输入预算

允许上传不等于承诺每轮发送全部原文。先排除未确认/移出范围来源；授权来源放得下就全文发送，超出剩余预算才按实际空间用分块 BM25 选择有原文行号的片段；无命中明确标记有限首尾背景。追问与会话测验共用一套稳定来源（预留固定动态空间），问答过长时先省略较早作答、保留最新一轮，完整记录仍保存。此后 H2 才处理 JSON/模型窗口预算，不固定截复述前 6,000 字符（见 ADR 0003）。原文和完整草稿不改变。检索与预算裁剪分开显示；局部片段不代表阅读全文、语义覆盖或已评估省略内容，字数占比也不是知识覆盖率。

除任务 JSON 48K 外，live 使用显式 Provider 本地目录 `contextWindow`，按完整系统提示 + 当前任务输出 Schema + 用户任务 JSON 的 UTF-8 字节数作保守输入 token 估算，再预留配置的输出 token 额度与 512-token 消息/Provider 适配余量。预留常量唯一来源为 `learning-agent/src/request.ts`。不使用字符除以四假装精确分词；估算偏保守，会比真实分词更早节选或拒绝，也不能保证厂商目录、封装或实际接受行为永远一致。OpenAI/Codex OAuth 输出预留不是上游硬上限或费用承诺。

共享 `prepareLearningRequest` 用于宿主事务内准备并持久化实际任务；引擎 `checkLearningRequest` 在读取凭据或请求 Provider 前再拒绝超限，不在执行时偷偷改变已准备内容。结构、系统提示与必要字段放不下时明确拒绝并保留原输入。尤其 **grade 不能截正式答案或 rubric 来换取成功**，正式答案提交前就按当前模型预检，拒绝时不锁定答案。

页面使用只读 `POST /api/recitations/:id/input-preview` 和 `POST /api/questions/:id/input-preview`，受 Cookie/Origin/CSRF 保护。服务端纳入当前已上传资料或当前题私有评分标准，仅返回数值/节选条目，不返回系统提示、资料正文、答案或凭据；预检不写库、不产生日志回执或 run、不调用模型或刷新凭据。`canSubmit` 仅表示输入预算通过，不表示账号连通。前端防抖、取消旧请求并按输入/版本丢弃迟到结果，正式提交前重检；草稿保存、上传和跳过不因预检失败而被禁止。历史学习页的资料管理不冒充原会话快照预算。

无需纳入的历史和移出范围资料不得再次外发。真实任务可能发送本次复述、被选片段、问题与作答；不是所有资料永远不离开本机。提示词版本为 `learning-v8`，旧 run 版本不回写；连接诊断仍为 `connection-v1`。

其他已有执行限制：每会话默认 20 次模型任务、默认超时 60 秒（最大 120 秒）、输出校验默认 4096 token。不自动重试 Provider 请求。OpenAI/Codex OAuth 的上游输出硬限制例外与费用风险见 README，不把事后校验当厂商侧硬上限。

### 本地资料库、联想参考与缓存

只读 `POST /api/library/search` 在当前模式的已存资料/知识中进行中文英文 BM25 检索，无模型、embedding 或写入。历史文档须经 `POST /api/recitations/:id/references` 明确附加；它仍保留上传出处并共享原文 ID，移除只解绑。开启“旧知识联想”设置后，确认范围和复习提交回忆时由本地 BM25 自动选出最多三个旧知识点并冻结内容版本，作为 `related` 供模型结合出题；它们不是可引用来源，不新增考核点，组合题只影响当前知识点的证据与排期，也不同于更新已有内容的知识点复用（见 ADR 0003）。生成题逐点核对来源。重试使用已持久化任务，不重新检索。

第三批补充：资料检索支持分页、显式个人理解搜索及版本化术语扩展；复习支持当前标签页连续队列、暂停卡片和可追溯统计。新增数据都是兼容旧备份的可选字段，统计不写库，评级仍为 mapping-v1。接口、统计口径与限制见 [ADR 0006](./decisions/0006-文本PDF与复习统计.md)。

`GET/PUT /api/learning/preferences` 管理模式隔离的排期、旧知识联想（默认关闭）及 `none/short` 提示缓存设置；写入需确认、CAS、幂等，活动任务期间拒绝。未保存时继承原排期环境默认，缓存 none。短缓存只尝试稳定前缀/会话亲和，不保证厂商命中或费用，none 不等于厂商完全关闭缓存。实际读/写计数是总输入的子集，旧记录缺计数标未知。详见 [ADR 0002](./decisions/0002-本地检索与显式知识关联.md)。

## 4. 架构与持久化

```text
浏览器 / Next.js（同源转发） → Fastify（身份、HTTP、生命周期）
                                      ↓
                       learning-domain（状态机与事务规则）
                          ↙                         ↘
               StateRepository                LearningEngine
           PGlite / Drizzle            Pi Agent / 显式 Provider
                                      （无工具，单请求结构化结果）
```

工作区及依赖已建立；Pi 发布包锁定 1.0.4，参考 `pi/` 不参与安装构建。静态设计已导入 `design/sanxing-design-handoff/`，未执行交接包插件或生成脚本。设计示意参数不直接成为业务规则。

### 单进程而非集群

- 同一数据库目录只允许一个应用进程，API 与维护脚本不能同时打开；使用合作进程目录锁。串行事务与 revision CAS 保证本进程提交顺序，不能据此宣称多进程吞吐。
- 无 tools / `propose_*` 提案通道、无多 worker 租约或接管。每个模型任务做一次无工具请求，结构化结果经 Schema、来源及活动版本检查后由宿主提交；不提供文件系统、SQL、Shell 或任意网络工具。
- 本轮采用入队后唤醒单执行器，取消空闲 worker 周期性全聚合读取；启动恢复与在途取消仍须处理，不因去轮询而自动重放付费请求。
- 客户端没有 SSE 消费；本轮直接移除旧 SSE。`GET /api/state?since=revision` 返回 `unchanged`、`snapshot` 或 `delta`（`upsert/remove`）；服务端只保留 16 个指纹基线，不保留 16 份完整状态，未知 revision 回快照。Web 使用 `compact=1` 首载摘要，已交卷测验详情及分页证据按需读取；其他实体仍全量同步。
- 资料全文只在登录后通过 `GET /api/documents/:id` 按需读取，首次状态不携带全文；`/api/me` 仅读内存小型设置投影，不查 SQL 或复制全量聚合。版本/增量协议及客户端应用已通过 API/E2E 回归，不是模型文本流式展示承诺。

### 两种 schema 版本不得混淆

物理数据库 **schema v4** 把文档原文放入 `app_documents`、AI 任务输入放入 `app_run_tasks`，测验及证据正文放入 `app_learning_records`，其余业务仍保存为聚合。已有物理 v1/v2/v3 通过事务升级；进程内快照缓存减少重复读取，写操作仍经串行事务/CAS。**学习 JSON 备份的 `AppData.schemaVersion` 仍为 1**，不是物理库版本。

这不是所有实体都已拆表：聚合内存占用和全聚合写校验成本仍存在。升级前必须停服，通过 `npm run data:export -- ./backup-before-v4.json --before-migration` 导出已有物理 v1/v2/v3/v4 数据，此专用路径加锁并在 SQL 只读事务中完整读取，不初始化或升级 schema。临时 v1 CLI 测试确认导出后 schema 仍 1、权限 0600、wx 不覆盖；PGlite 可自身 WAL 恢复，不承诺磁盘零写，也不需要找回旧程序。新物理库不能由旧程序直接打开。回退须使用独立恢复路径及原备份，不原地降级。具体操作见 README；本轮不操作或声称已迁移用户真实数据库。

### 规模目标与保留

工程目标是**单用户、≤1,000 知识点、≤500 份资料、≤1 年日常记录**。已用合成样例覆盖此规模（见 ADR 0007），仍是**非强制总量上限、非延迟保证**；超过后观察逻辑 JSON 导出大小、状态传输及读写延迟，再决定分页、归档或拆更多实体，不自动删除学习历史。

PGlite 磁盘目录含引擎固定开销、WAL 等，目录为 39M 不能证明逻辑学习资料已很大，更不能由此断言使用数月必然变慢。

- 已知的 CAS 草稿/理解/回忆暂存回执，在后续新命令中按 24 小时、最多 2,000 条清理；含 `runId`、未知操作及其他非暂存收据长期保留，不是所有非计费命令都自动删除。清理窗口内靠幂等回执，过期后的并发安全还依赖业务版本/唯一性，不能承诺暂存请求无限期去重。
- **含 `runId` 的付费任务及连接测试收据不自动删除**，避免旧 key 重放收费操作。手动清空或恢复旧备份不享有跨备份的永久防重放保证。
- 学习记录、证据和资料原文不自动到期；用户手动导出/逻辑清空。清空不等于抹除旧备份、WAL 或厂商已收到的数据。
- 学习 JSON 导出是未加密私人资料；OAuth vault 独立保存，不包含在学习导出内。密钥保全与恢复边界见 README。

## 5. 安全、配置与计量

单用户不等于无访问保护：密码会话验证身份，资源归属防止越界，Cookie 写接口通过 CSRF / Origin 防止浏览器跨站滥用。它们防御不同问题，不是多租户或多重登录设计，详见 ADR。

保持开发 Web `0.0.0.0:3010` 便于 WSL 访问，API 为 `127.0.0.1`。真实客户端 IP 采用受控代理：Next 自定义 Node 入口从 socket `remoteAddress` 取 IP，剥离客户端转发头，使用 HMAC 绑定 IP、时间、方法和 path；API 只在请求来自 loopback 且签名有效时采纳该 IP，继续 `trustProxy:false`。不信任任意 `X-Forwarded-For`，也不以 Origin 白名单替代登录限流。**已通过离线代理与 API 回归，真实 Next 新入口通过 E2E**。Web dev/start 必须经 npm scripts → `apps/web/server.mjs`，不支持直接 `next dev/start`；`API_INTERNAL_URL` 只接受 literal loopback origin（127.* / ::1），不是 localhost hostname 或远程 API。Upgrade 仅 dev `/_next/hmr`（可 query）放行，生产及未知路由拒绝，退出销毁已跟踪的升级 socket；12 个 Node socket 测试覆盖。NAT 在入口前合并的源 IP 不能靠不可信头恢复。本轮未人工验收 Windows→WSL 真实网络访问，仍仅在可信本机网络使用；生产 HTTPS 需独立受控部署，不扩大信任，不据此宣称公网审计通过。

配置实现来源只有 [`.env.example`](../.env.example) 与 `apps/api/src/config.ts`（Web 专属启动参数见 README）。不新增历史草案变量；`MODEL_BASE_URL` 未实现且设置后会拒绝启动。独立 AuthContext 不是 OS 沙箱，live 环境的厂商/代理/TLS 污染检查不因开发便利而弱化。报告 L6 所称错误未指出变量名不符合既有实现，应保留其诊断与隔离能力。

**当前已确定不设应用金额预算**，不是待决定项。以后仍可显式同时配置已有日预算与请求预留；超时、调用次数和已知/未知用量继续记录。结果内容及引用有效但 usage 缺失时仍可成功，计量保留 `null` / 未知；启用预算时保留相应预留，不能把未知变成免费。取消、失败、重启不证明上游未收费。

OAuth/vault、SESSION_SECRET 轮换、账号撤销、手动连接测试与上游限额例外集中维护于 README；不在各模块复制一份风险清单。
